Cache-Aside Under Load

An ALB fronting a VPC-attached Lambda that reads through ElastiCache and falls back to RDS. The design exists to make one thing measurable: what a cache miss actually costs when hundreds of requests arrive at once.

Region us-east-1 IaC Terraform, 20 resources State s3://744998/lab4 Tests PowerShell

What keeps latency flat as concurrency climbs

Lambda will happily scale to 200 concurrent executions. Every mechanism below exists to make sure that RDS is not what happens next.

module-scope clients
The MySQL and Redis connections are built once per execution environment and held outside the handler. A warm invocation opens no sockets. Move that construction inside handler() and 200 concurrent requests become 200 new MySQL connections.
volatile-lru
A full cache evicts its coldest key instead of returning OOM errors. The failure mode this avoids is silent: every write starts failing, every read falls through, and the database absorbs the entire load while the cache still reports healthy.
fail-open cache
Every Redis call is wrapped and falls through to MySQL on error, reporting X-Cache: UNAVAILABLE. A cache outage costs latency, not availability.
reserved = 200
Half the account's 400-execution ceiling. It caps how hard the function can hit RDS, and guarantees the capacity is there when it needs it.
provisioned = 0
Off by default because it bills hourly. Raise it to 10–20 immediately before a load test to take cold starts out of the p99, then put it back.
1024 MB
CPU is allocated in proportion to memory, so this is a CPU setting wearing a memory label. It roughly halves JSON and MySQL protocol parsing against the 128 MB default.

Endpoints

Every response carries source, cache_ms, db_ms and total_ms.
RouteBehaviour
/product?id=42 Cache-aside read. HIT or MISS in X-Cache.
/product?id=42&nocache=1 Identical query, cache skipped entirely. This is the control.
/init Applies sql/schema.sql. Terraform invokes this once at the end of apply — RDS is private, so the in-VPC function is the only path to it.
/stats Redis hit rate and key count, MySQL row counts and Threads_connected.
/flush Empties the cache, so a run can start cold.
The schema deliberately leaves products.category and reviews.product_id unindexed. Indexing them would make the uncached path fast and erase the effect this lab is built to measure — the comment saying so is load-bearing, not a TODO.
